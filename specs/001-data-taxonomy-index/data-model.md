# Data Model: SSYK Occupation Dataset and Bilingual Search Index

Pydantic v2 models in `src/lonekrav/core/models.py`. These are the single contract that later features
(API, MCP, A2A, React) reuse.

## SourceRef

| Field | Type | Rule |
|---|---|---|
| `source` | enum `scb_structure`, `scb_english`, `scb_title_index`, `scb_isco_key`, `scb_mis2012`, `scb_pxweb`, `jobtech`, `ilo_isco08`, `esco`, `sfs` | required |
| `ref` | str | table id, file name, URI or SFS number |
| `url` | str | where it was fetched from |

## Text

`lang` (`sv`|`en`), `text` (non-empty), `kind` (`definition`, `tasks`, `included_occupations`,
`excluded`), `source: SourceRef`, `isco_code: str | None` (set for ILO texts), `shared_with:
list[str]` (codes that share this text, for example 1211 and 1212).

## Synonym

`lang`, `label`, `source: SourceRef`, `jobtech_id | esco_uri: str | None`, `match_type: exact | close
| broad | narrow | None` (ESCO only). Unique on (`lang`, case-folded `label`); official sources win
over later ones.

## LegalFlag

| Field | Type | Rule |
|---|---|---|
| `kind` | `exempt_75` \| `banned` \| `partially_banned` | |
| `note` | str | for example "forest berry pickers only" |
| `effective_from` | date | 2026-06-01 for SFS 2026:605 |
| `source` | SourceRef | `sfs`, ref `SFS 2026:605`, the 5 kap. paragraph |

Codes: `exempt_75` for 3115, 3215, 3511, 3512, 3513, 3514, 5321, 5322, 5323, 5324, 5325, 5326, 5330,
6121, 6129, 6130, 6210, 7212, 7215, 7233, 7413, 7611, 8161, 8169, 8199, 8341 and 9210 (27); `banned`
for 5343; `partially_banned` for 9210. 9210 carries both flags, as the ordinance lists it in both
paragraphs. The list lives in `core/legal_flags.py` as data with the SFS citation and is checked by a
test against the ordinance text.

## OccupationProfile (one per code; 429 rows)

| Field | Type | Rule |
|---|---|---|
| `code` | str, 4 digits | primary key; in the TAB5932 code list |
| `title_sv` | str | SCB structure, else the TAB5932 label |
| `title_en` | str | SCB English, else the ILO title (military codes) |
| `isco_codes` | list[str] | SCB key, split on commas, at least one |
| `jobtech_concept_id` | str \| None | |
| `jobtech_shared` | bool | true when JobTech merges this code into a level-0 code |
| `descriptions` | list[Text] | at least one with `lang=sv` |
| `synonyms` | list[Synonym] | |
| `legal_flags` | list[LegalFlag] | |
| `sources` | list[SourceRef] | each source that contributed |

## SourceCoverage (discrepancies.csv; 429 rows)

`code`, `in_structure`, `in_english`, `in_salary_table`, `in_isco_key`, `in_title_index`,
`in_jobtech`, `jobtech_code` (the merged code, if any), `note`.

## SalaryDistribution (salary_distributions.parquet; one row per code × year, plus 0000)

| Field | Type | Rule |
|---|---|---|
| `code` | str | 0000 is the national reference |
| `year` | int | 2014 onwards |
| `mean`, `median`, `p10`, `p25`, `p75`, `p90` | int \| null | SEK per month; null means suppressed |
| `*_ci95` | int \| null | half-width; always null before 2023 |
| `suppressed` | list[str] | names of null fields |
| `source_table` | str | `TAB4265` or `TAB5932` |
| `reference_year` | int | equals `year` |
| `fetched_at` | datetime (UTC) | time the raw file was downloaded |

Validation: `p10 ≤ p25 ≤ median ≤ p75 ≤ p90` where all five are present. A violation fails the build
rather than being corrected.

## AgeBandSalary (salary_age.parquet; code × year × band)

`code`, `year`, `age_band` (`18-24`, `25-34`, `35-44`, `45-54`, `55-64`, `65-68`, `all`),
`mean_monthly` (int|null), `headcount` (int|null), `mean_ci95` (int|null), `suppressed`,
`source_table` (`TAB4264`|`TAB5844`), `reference_year`, `fetched_at`. The SCB band 65–66 is not
stored (it was replaced by 65–68).

## Chunk (Milvus collection `occupation_chunks`; derived, not committed)

`chunk_id` (`{code}:{kind}:{n}`), `code`, `kind` (`title`, `desc_sv`, `desc_en`, `synonyms_sv`,
`synonyms_en`), `lang` (`sv`|`en`|`mixed`), `text` (≤ 2 000 characters), `vec_kblab` (768),
`vec_harrier` (1024), `bm25` (sparse, generated by the BM25 function). The title chunk holds both
titles. Synonym chunks hold at most 40 labels and 2 000 characters each. Hold-out benchmark titles
are removed before chunking. A local index keeps its analysis vocabulary in `<db>.vocab.json`.

## SearchHit (returned by `core.search`)

`code`, `title_sv`, `title_en`, `scores: {kblab, harrier, bm25}` (float|None; higher is better;
None when that method did not rank the code within its candidate pool), `ranks: {kblab, harrier,
bm25}`, `fused_score`, `fused_rank`, `matched_chunk: {kind, text}` (best chunk from the top-scoring
method).

## BenchmarkQuery / BenchmarkResult

Query: `id`, `origin` (`handwritten`|`generated`), `type` (`title`, `duty_sentence`, `description`,
`lookalike`), `text_en: str | None`, `text_sv`, `expected_codes: list[str]` (at least one).

Result file `benchmark_results.json`: `run_at`, `models: {kblab: hf_id@revision, harrier: …}`,
`n_queries` by origin and language, and `metrics[method][lang][origin] = {recall_at_1, recall_at_5,
mrr, n}`, plus `gap_recall_at_5[method][origin] = en − sv`.
